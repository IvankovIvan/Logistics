Project №1.4.c — Источник и семантика quantity склада (write-side)

Цель
Зафиксировать единственный корректный источник поля quantity для склада, не ломая ingest, current-state и инварианты Project №1.

⸻

Исходные факты (зафиксированы ранее)
	•	/api/map — витрина текущего состояния, не аналитика.
	•	Read-side ничего не считает.
	•	Quantity не может вычисляться:
	•	из маршрутов,
	•	из “в пути”,
	•	на фронте,
	•	через агрегации.
	•	Единственный допустимый источник истины — write-side события.

⸻

Архитектурное решение (принято)

Quantity задаётся напрямую в событиях склада

👉 Склад — владелец своего количества.

⸻

Семантика события склада

Событие типа warehouse обязано содержать:
{
  "id": "warehouse_id",
  "quantity": number,
  "...": "другие поля склада"
}

Смысл
	•	quantity — абсолютное значение, не дельта;
	•	заменяет предыдущее значение при применении события;
	•	подчиняется тем же правилам:
	•	event_time,
	•	stale-защите,
	•	idempotency.

⸻

Почему НЕ дельты

Подход                          Причина отказа
+10 / -5                        требует истории
вычисление из маршрутов         превращает read-side в аналитику
“остаток = вчера + сегодня”     ломает current-state
фронтовая агрегация             запрещено

Абсолютное значение:
	•	детерминировано,
	•	идемпотентно,
	•	легко пересылается повторно,
	•	безопасно при out-of-order.

⸻

Обновление current-state

warehouses_current.quantity:
	•	перезаписывается только если event_time >= last_event_time;
	•	stale-события не меняют quantity;
	•	duplicate-события игнорируются.

Поведение полностью совпадает с существующей логикой склада.

⸻

Влияние на существующие этапы

Project №1.1–1.2
	•	ingest-механика не меняется;
	•	добавляется одно поле в payload;
	•	stale / duplicate семантика уже готова.

Project №1.3
	•	маршруты не затрагиваются.

Project №1.5
	•	становится возможным:
	•	масштаб точек,
	•	числовые подписи,
	•	визуальная семантика складов.

⸻

Что сознательно НЕ делаем здесь
	•	не вводим supply/sale;
	•	не считаем “в пути”;
	•	не меняем API;
	•	не добавляем историю.

⸻

Итог
	•	Quantity — write-side ответственность.
	•	/api/map остаётся витриной.
	•	Архитектура остаётся чистой и расширяемой.
