# 🚀 Project Start Template (Production Style)

## 0. Правила работы

Работаем строго по процессу:

Step → Verify → Update md → Commit

---

## 1. Контекст проекта

Опиши:

- цель проекта:
- что строим:
- где будет использоваться:
- входные данные:
- выходные данные:

---

## 2. Ограничения

- стек (FastAPI / Postgres / etc)
- Docker (да/нет)
- ORM (да/нет)
- требования к производительности
- объём данных

---

## 3. Архитектурные принципы

Зафиксировать:

- source of truth
- слои (router / service / db)
- тип хранения данных
- синхронность / асинхронность
- batch / realtime

---

## 4. MVP (обязательно)

Определи минимальную версию:

- какие endpoint'ы нужны
- какие данные
- без UI или с простым UI

---

## 5. Разбиение на шаги

Сделать план:

- шаг 1
- шаг 2
- шаг 3
- ...

Каждый шаг должен быть:
- проверяемый
- независимый
- коммитимый

---

## 6. Документация

Создать файл:

/docs/_work/project-X.md

---

## 7. Первый шаг

Начать с самого простого:

обычно:
- metadata endpoint
или
- базовая таблица

---

## 8. Формат работы с ChatGPT

- сначала обсуждение шага
- потом PROMPT для Copilot
- потом проверка
- потом фиксация

---

## 9. Swagger

Сразу:

- Pydantic модели
- response_model
- описание endpoint

---

## 10. Проверка

Каждый шаг проверяется:

- API
- Swagger
- данные

---

## 11. Запрещено

- делать сразу всё
- писать код без шага
- менять архитектуру без обсуждения

---

## 12. Цель

Сделать:

- расширяемую систему
- чистую архитектуру
- воспроизводимый процесс
