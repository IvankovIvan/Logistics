# 📘 Project №6 — Code Cleanup & Full Removal of Legacy (V2)

---

## 1. Цель

Project №6 — полное удаление неиспользуемой подсистемы Project №1
(OLTP map + ingest + datasource + DB + docker)

Назначение:

- удалить неиспользуемый функционал
- упростить архитектуру
- зафиксировать реальное состояние системы

---

## 2. Общая идея

Система полностью перешла на analytics слой (Project №3 и №5).

Project №1:

- не используется frontend’ом
- не используется ingest’ом
- не используется API

Вывод:

Project №1 — legacy, подлежит удалению

---

## 3. Стратегия удаления

Удаление выполняется строго сверху вниз:

API → Service → DataSource → Ingest → Database → Docker

Правило:

после КАЖДОГО шага выполняется проверка системы

---

## 4. Область работ

Включает:

- router `/api/map`
- сервисы Project №1
- datasource selector
- старый ingest (`/api/ingest`)
- таблицы OLTP:
  - warehouses_current
  - shipments_current
- docker / env конфигурацию

Не включает:

- analytics (Project №2, №3, №5)
- ingestion pipeline (Project №4)

## 6. Принятое решение

Project №1 удаляется полностью.

Удаление выполняется поэтапно:

1. отключение router
2. удаление service слоя
3. удаление datasource
4. удаление ingest
5. удаление таблиц
6. удаление docker/config

---

## 7. Ожидаемый результат

- система работает только на analytics
- нет legacy API
- нет лишних таблиц
- кодовая база упрощена

---

## 8. Ограничения

1. удаление строго по шагам
2. после каждого шага проверка
3. не трогать analytics слой
4. не нарушить работоспособность системы

---

## 9. Риски

1. скрытые зависимости
2. случайное использование legacy
3. ошибки при удалении БД

Решение:

- поэтапная проверка
- постепенное отключение

---

## 10. Инварианты

1. `/api/analytics/*` остаётся основным API
2. frontend работает только с analytics
3. ingestion Project №4 не затрагивается
4. система остаётся работоспособной на каждом шаге
