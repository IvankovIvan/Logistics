# 📘 Project №3 — Analytics Map Architecture (V1)

---

## 1. Цель

Project №3 — визуализация аналитических данных (Project №2) на карте.

Назначение:

* отображать текущее состояние складов
* визуализировать агрегированные данные
* предоставить аналитический слой поверх snapshot
* быть независимым от OLTP

---

## 2. Общая архитектура

```
analytics.current_batch_state → aggregation → /api/analytics/map → frontend
```

---

## 3. Источники данных

### 3.1 Snapshot

```
analytics.current_batch_state
```

Хранит:
* активные партии
* их статус и количество

---

### 3.2 География

```
analytics.warehouses
```

Хранит:
* warehouse_id
* lat / lon
* name

---

## 4. Логика агрегации

Агрегация выполняется на лету:

```
GROUP BY warehouse_id, status_id, status_reason_id
```

Результат преобразуется в:

* total_quantity
* by_status
* by_reason

---

## 5. API

Endpoint:

```
GET /api/analytics/map
```

---

## 6. Формат ответа

```
{
  "warehouse_id": 1,
  "lat": 59.93,
  "lon": 30.31,
  "metrics": {
    "total": 120,
    "by_status": [...],
    "by_reason": [...]
  }
}
```

---

## 7. Визуализация

Карта отображает:

* точки складов
* переключаемые слои:
  * общий объем
  * статусы
  * причины

---

## 8. Пустые склады

Склады без активных партий:

* отображаются
* имеют значение 0
* визуализируются отдельно (например, серым)

---

## 9. Ограничения

1. Агрегация выполняется на лету
2. Нет маршрутов (будут добавлены позже)
3. Возможны ограничения по производительности

---

## 10. Инварианты

1. Источник данных — только analytics
2. Нет зависимости от OLTP
3. Snapshot — единственный источник состояния
4. География хранится отдельно

---

## 11. Итог

Project №3 реализует:

* аналитическую карту
* агрегированные метрики
* визуализацию snapshot данных
