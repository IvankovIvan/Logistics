# Dev guidelines

## Принципы

- **Идём по одному шагу**: одно изменение → проверка → коммит.
- **Документация живёт в репо** (`docs/*`), без внешних «знаний в голове».
- **Комментарии в коде**: почему так сделано и где менять при переходе на БД/ингест.
- **Стабильный контракт API**: фронт не должен страдать от внутренних рефакторингов.

## Стиль кода (Python)

- Используем типы (`typing`, `Protocol`, enum’ы).
- Не добавляем новые зависимости (типа `httpx`) без явной установки в образ.
- В роутерах минимум логики: сборка в `services/*`, «примитивы» в `domain/*`.

Рекомендованный линтер: `ruff`.

## Рефакторинг через Codex

1) Сформулировать цель (например: «уменьшить routers/map.py, вынести в services/domain»).
2) Попросить Codex:
   - сохранить контракт API,
   - добавить комментарии на русском,
   - не тянуть новые зависимости без согласования.
3) После правок:
   - `docker compose up -d --build app`
   - `curl http://127.0.0.1/api/health`
   - `curl http://127.0.0.1/api/map`
4) Потом коммит.

## Быстрые команды

```bash
cd ~/infra/nginx
docker compose up -d --build
docker compose ps
docker compose logs -f app
curl -sS http://127.0.0.1/api/health; echo
curl -sS http://127.0.0.1/api/map | head -c 300; echo
```
