# 🗄️ Repository Standards (обязательные правила)

## 1. Общие принципы

- Repository — единственное место, где есть SQL
- Repository работает только с БД
- Repository не содержит бизнес-логики
- Repository возвращает "сырые" данные (dict)

---

## 2. SQL

- SQL хранится:
  - либо как константы
  - либо в queries.py

- Запрещено:
  - писать SQL в router
  - писать SQL в service

---

## 3. Возвращаемые данные

- Repository возвращает:

    list[dict]
    dict | None

- Запрещено возвращать:
  - Pydantic модели
  - классы

---

## 4. Типы данных

- Все значения из БД считаются невалидированными
- Типизация происходит НЕ в repository

---

## 5. Connection

- Используется единый метод:

    get_analytics_connection()

- Запрещено:
  - создавать соединение вручную
  - дублировать connection-код

---

## 6. Параметры запросов

- Используются только именованные параметры:

    %(warehouse_id)s

- Запрещено:
  - f-string в SQL
  - конкатенация строк

---

## 7. Безопасность

- Все запросы параметризованы
- SQL-инъекции недопустимы

---

## 8. Структура

Пример:

    def get_warehouses(conn) -> list[dict]:
        with conn.cursor() as cur:
            cur.execute(SQL_GET_WAREHOUSES)
            return cur.fetchall()

---

## 9. Разделение ответственности

- repository:
  - SQL
  - получение данных

- service:
  - логика
  - агрегация

- mapper:
  - преобразование в модели

---

## 10. Инварианты

- Repository не знает про API
- Repository не знает про frontend
- Repository не возвращает готовые модели
