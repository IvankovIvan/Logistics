Project №1.5.a — Warehouses Geometry Invariants

⸻

1. Назначение шага

Project №1.5.a закрывает геометрическую семантику складов на карте в рамках Project №1.

Цель шага — обеспечить корректное, устойчивое и однозначное визуальное представление абсолютного текущего количества товара на складе, без добавления интерактивности, аналитики или бизнес-логики на фронте.

Этот шаг намеренно ограничен только геометрией точек складов и является фундаментом для:
	•	подписей (Project №1.5.b),
	•	общего итога,
	•	дальнейшего расширения визуала без рефакторинга базовой геометрии.

⸻

2. Инварианты визуализации складов

Жёстко зафиксированы следующие инварианты:
	•	Каждый склад всегда видим на карте.
	•	Геометрия складов не содержит бизнес-логики.
	•	Визуализация использует абсолютное значение quantity, полученное из API.
	•	Отсутствие quantity у склада считается ошибкой контракта, а не допустимым состоянием.
	•	Frontend ничего не считает и не агрегирует.
	•	Радиус кодирует только quantity и не зависит от других параметров.
	•	Масштаб радиуса не зависит от распределения данных.

⸻

3. Источник данных

Единственный источник данных для геометрии складов:

GET /api/map
  → MapWarehouse.quantity

Свойства:
	•	quantity — абсолютное текущее значение.
	•	Значение уже является current-state.
	•	Frontend не интерпретирует происхождение quantity.
	•	Любые дельты, суммы, перерасчёты запрещены.
	•	Если API возвращает склад без quantity — это ошибка backend-контракта.

⸻

4. Геометрическая модель склада
	•	Тип слоя: MapLibre circle-layer
	•	Геометрия: Point (lon, lat)
	•	Соответствие:
1 склад = 1 feature

Координаты склада:
	•	фиксированы,
	•	не изменяются масштабом,
	•	не зависят от состояния или quantity.

Порядок слоёв:
	•	Слой складов располагается под маршрутами.
	•	Геометрия складов не перекрывает семантику движения (Project №1.3).

⸻

5. Масштабирование радиуса точки (ОКОНЧАТЕЛЬНЫЙ СТАНДАРТ)

Причина изменения

Первоначальная формула:

minR + k * log10(quantity + 1)

оказалась нестабильной при длинном хвосте распределения (значения 10k–35k+ визуально раздували карту).

Поэтому введена bounded log-scale нормализация.

⸻

Фиксированный диапазон нормализации

WAREHOUSE_Q_MIN = 100
WAREHOUSE_Q_MAX = 1000

Интерпретация:
	•	quantity ≤ 100 → минимальный радиус
	•	quantity ≥ 1000 → максимальный радиус
	•	100–1000 → логарифмическая интерполяция

⸻

Математическая модель

norm = clamp(
  (log10(quantity) - log10(WAREHOUSE_Q_MIN)) /
  (log10(WAREHOUSE_Q_MAX) - log10(WAREHOUSE_Q_MIN)),
  0,
  1
)

radius = minR + norm * (maxR - minR)

Так как:

log10(100)  = 2
log10(1000) = 3

выражение упрощается внутри MapLibre expression.

⸻

Архитектурная фиксация
	•	Вычисление выполняется исключительно в circle-layer expression.
	•	transform.ts не содержит логики масштабирования.
	•	JS-код не вычисляет радиус.
	•	Никакой динамической нормализации по данным не допускается.
	•	Диапазон 100–1000 является фиксированным стандартом Project №1.

Важно:
	•	Это чисто визуальная функция.
	•	Она не отражает экономическую модель.
	•	Она не зависит от текущего распределения данных.
	•	Она воспроизводима во всех средах.

⸻

6. Константы визуализации

Фронтенд-константы:
	•	WAREHOUSE_MIN_R
	•	WAREHOUSE_MAX_R
	•	WAREHOUSE_Q_MIN
	•	WAREHOUSE_Q_MAX

Они:
	•	являются частью визуального стандарта,
	•	не вычисляются динамически,
	•	не зависят от окружения,
	•	могут изменяться только через осознанное архитектурное решение.

9. Критерии готовности (Definition of Done)

Шаг считается завершённым, если:
	•	Любое quantity ≥ 0 отображается.
	•	quantity = 0 визуально различимо.
	•	Малые значения (1–100) не доминируют.
	•	Средние значения (100–1000) различимы.
	•	Большие значения (>1000) ограничены maxR.
	•	Масштабирование стабильно при любых данных.
	•	Масштаб не зависит от числа складов.
	•	Ни один другой слой не зависит от quantity.
	•	Геометрия складов не требует рефакторинга в следующих этапах.

⸻

10. Осознанные ограничения

Project №1.5.a не включает:
	•	подписи;
	•	числовые значения на карте;
	•	tooltip;
	•	интерактивность;
	•	аналитику;
	•	изменения API;
	•	изменения ingest;
	•	изменения Project №1.3.

Это сознательные границы шага.
