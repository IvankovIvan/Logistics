🎯 Цель этапа

Реализовать геометрическую семантику маршрутов на основе shipment.volume, строго следуя принципам Project №1:
	•	volume кодируется только толщиной линии
	•	без аналитики
	•	без агрегации
	•	без вычислений на фронте
	•	без изменений API
	•	без нарушения архитектуры Project №1.3

⸻

📌 Контекст

Project №1.6.a:
	•	shipment.volume — first-class current-state поле
	•	/api/map гарантирует volume
	•	read-side ничего не считает
	•	frontend получает абсолютное значение

Теперь необходимо:

Закодировать volume в геометрию маршрута.

⸻

🧱 Принцип визуальной модели

1️⃣ Один маршрут = одна feature
	•	Нет агрегации
	•	Нет объединения
	•	Нет геометрических модификаций
	•	Нет изменения direction

Offset остаётся только для визуального разведения направлений.

⸻

2️⃣ Volume кодируется исключительно line-width

Формула (аналогично складам):

width = clamp(
  minW + k * log10(volume + 1),
  minW,
  maxW
)

Реализация через MapLibre expression:

ln(volume + 1) / ln(10)

📐 Константы (единый источник правды)

Добавляются в:

web/src/app/map/constants.ts

Предлагаемые значения:

ROUTE_MIN_W = 1.5
ROUTE_MAX_W = 8
ROUTE_K     = 2.5

🔒 Инварианты

✔ volume ≥ 0 всегда отображается
✔ volume = 0 остаётся тонкой линией
✔ большие значения не доминируют
✔ цвет не кодирует volume
✔ направление не зависит от volume
✔ стрелки не изменяются
✔ hover логика не меняется
✔ фильтр статусов не ломается
