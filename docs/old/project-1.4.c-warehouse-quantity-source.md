Project №1.4.c — Источник и семантика quantity склада (write-side)

Цель

Зафиксировать единственный корректный источник поля quantity для склада, не ломая ingest, current-state и инварианты Project №1.

⸻

Исходные факты
	•	/api/map — витрина текущего состояния, не аналитика.
	•	Read-side ничего не считает.
	•	quantity не может вычисляться:
	•	из маршрутов,
	•	из “в пути”,
	•	на фронте,
	•	через агрегации.
	•	Единственный допустимый источник истины — write-side события.

⸻

Архитектурное решение

quantity задаётся напрямую в событиях склада.
Склад является владельцем своего количества.

⸻

Семантика события склада

Событие типа warehouse обязано содержать поле:
quantity: number

Смысл:
	•	quantity — абсолютное значение, не дельта;
	•	при применении события полностью заменяет предыдущее значение;
	•	подчиняется тем же правилам, что и остальные поля склада:
	•	event_time,
	•	stale-защита,
	•	idempotency.

⸻

Обязательность
	•	Событие склада без поля quantity считается логически некорректным.
	•	Такое событие подлежит отклонению (rejected).
	•	Read-side и /api/map не обязаны и не имеют права обрабатывать склады без quantity.

⸻

Почему не дельты
	•	дельты требуют истории;
	•	вычисления превращают read-side в аналитику;
	•	“остаток = вчера + сегодня” ломает current-state;
	•	фронтовая агрегация запрещена.

Абсолютное значение:
	•	детерминировано,
	•	идемпотентно,
	•	безопасно при out-of-order,
	•	легко повторно передаётся.

⸻

Обновление current-state

warehouses_current.quantity:
	•	перезаписывается только если event_time >= last_event_time;
	•	stale-события не меняют quantity;
	•	duplicate-события игнорируются.

Поведение полностью совпадает с существующей логикой current-state складов.

⸻

Влияние на существующие этапы
	•	Project №1.1–1.2: ingest-механика сохраняется, добавляется обязательное поле;
	•	Project №1.3: маршруты не затрагиваются;
	•	Project №1.5: становится возможной визуальная семантика складов.

⸻

Что сознательно НЕ делаем
	•	не вводим supply/sale;
	•	не считаем “в пути”;
	•	не добавляем историю;
	•	не расширяем аналитику.

⸻

Итог

quantity — строгая write-side ответственность.
/api/map остаётся витриной current-state.
Архитектура остаётся простой и расширяемой.
