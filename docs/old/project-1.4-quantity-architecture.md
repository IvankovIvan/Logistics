Project №1.4.a — Quantity as Current-State (архитектурная фиксация)

Цель
Добавить абсолютное текущее количество товара на складе в систему Project №1 так, чтобы:
	•	не ломать Project №1.1–1.3,
	•	сохранить модель “экран на сейчас”,
	•	не превращать витрину в аналитику,
	•	дать фронту данные для визуальных инвариантов складов.

⸻

Определение quantity

quantity — абсолютное текущее количество товара, находящегося на складе в момент “сейчас”.

Инварианты:
	•	не производная величина,
	•	не вычисляется из маршрутов,
	•	не агрегируется на read-side,
	•	не хранит историю,
	•	может быть 0.

⸻

Источник правды

Единственный источник правды для quantity — current-state склада.

Quantity:
	•	приходит в систему явным событием,
	•	хранится как часть warehouse current-state,
	•	читается read-side напрямую, без расчётов.

⸻

Где живёт quantity

Логически:
	•	в сущности Warehouse (current-state)

Архитектурно:
	•	тот же уровень, что и координаты склада,
	•	обновляется по тем же правилам:
	•	idempotency,
	•	защита от out-of-order (event_time).

⸻

Что НЕ делает система

Система осознанно не:
	•	считает quantity из:
	•	поставок,
	•	продаж,
	•	маршрутов,
	•	разницы входов/выходов;
	•	не пересчитывает quantity “на лету”;
	•	не пытается быть системой учёта.

Это не аналитика и не бухгалтерия — это витрина “на сейчас”.

⸻

Событийная модель (концептуально)

Quantity изменяется только событиями типа:

“warehouse state update”

Семантика:
	•	событие содержит полное значение quantity,
	•	последнее по event_time побеждает,
	•	устаревшие события → stale.

⸻

Попадание в /api/map

Поток данных:
warehouse current-state (quantity)
        ↓
read-side data source
        ↓
map_builder
        ↓
/api/map → MapWarehouse.quantity
Read-side:
	•	не знает, как получено quantity,
	•	просто отображает текущее состояние.

⸻

Гарантии совместимости
	•	Project №1.1 (ingest, idempotency) — не ломается.
	•	Project №1.2 (semantic fix ingest) — сохраняется.
	•	Project №1.3 (routes visualization) — не затрагивается.
	•	Frontend получает ровно то, что ему нужно для 1.5.

⸻

Осознанные ограничения
	•	Нет истории изменений quantity.
	•	Нет вычислений “в пути”.
	•	Нет попытки вывести “ожидаемое количество”.

Это будет отдельный проект, не Project №1.

⸻

Итог

После принятия этого решения:
	•	quantity становится first-class current-state полем,
	•	/api/map может честно отдать абсолютные значения,
	•	Project №1.5 (Warehouses Visual Semantics) разблокирован.
