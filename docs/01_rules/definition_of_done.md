# ✅ Definition of Done (DoD)

## 1. Назначение

Definition of Done — критерии, при которых задача считается завершённой.

Задача НЕ считается завершённой, если хотя бы один пункт не выполнен.

---

## 2. API

- endpoint реализован
- есть response_model
- Swagger полностью описан:
  - summary
  - description
  - модели

---

## 3. Архитектура

- соблюдены слои:

    router → service → mapper → repository

- нет обхода слоёв

---

## 4. Код

- нет:
  - SQL вне repository
  - dict в API
  - object / Any без причины

- используется mapper
- используется Pydantic

---

## 5. Repository

- SQL только в repository
- запросы параметризованы
- нет бизнес-логики

---

## 6. Mapper

- все поля приведены к типам
- datetime обработан
- возвращается Pydantic

---

## 7. Service

- нет SQL
- нет HTTP
- возвращает модели

---

## 8. Frontend (если затронут)

- endpoint используется
- нет хардкода URL
- типы соответствуют API

---

## 9. Документация

- изменения отражены:
  - в project-*.md (если влияет на архитектуру)
  - в standards (если изменились правила)

---

## 10. Audit

- пройден code audit
- нет нарушений стандартов

---

## 11. Коммит

- есть commit message
- описано:
  - что сделано
  - зачем

---

## 12. Финальный статус

Задача считается завершённой только если:

    ВСЕ пункты = OK

Иначе:

    статус = FAIL
