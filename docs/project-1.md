# Project №1 — Logistics  
## Текущее состояние логистики (на сейчас)

## Статус
**Завершён**  
- Project №1.1 — current-state ingest  
- Project №1.2 — semantic fix ingest (v1.2.0)

---

## 1. Цель проекта

Project №1 — это **экран наблюдения**, показывающий текущее состояние логистики
**одного товара** в системе **на текущий момент времени**.

Проект отвечает на вопросы:
- где товар находится сейчас,
- как он перемещается между складами,
- сколько товара всего в системе прямо сейчас.

Проект **не предназначен** для управления, аналитики или истории.

---

## 2. Область ответственности

### Входит в Project №1
- отображение складов на карте;
- отображение межскладских перемещений;
- отображение поставок и продаж;
- агрегированное текущее состояние (“current-state”);
- автообновление данных;
- обработка ошибок обновления;
- минималистичный визуал без интерактивных действий.

### Не входит в Project №1
- история и динамика;
- статусы складских операций;
- фильтры и аналитика;
- пользовательские настройки;
- авторизация и роли.

---

## 3. Модель данных (концептуально)

### Основные сущности
- **Склад**
  - фиксированные координаты;
  - короткое имя + номер;
  - остаток товара на текущий момент.

- **Перевозка**
  - уникальный `transfer_id`;
  - фиксированное количество;
  - жизненный цикл (статус обновляется);
  - “в пути сейчас” = сумма активных перевозок.

- **Поставка / продажа**
  - отдельные сущности;
  - в Project №1 считаются мгновенными;
  - модель допускает расширяемые статусы в будущем.

### Принципы
- события могут приходить в любом порядке;
- строгая идемпотентность по `event_id`;
- хранится только текущее состояние;
- история добавляется в будущих проектах.

---

## 4. Ingest (write-side)

### Контракт
- данные приходят через HTTP API;
- поддерживается batch-запись;
- каждое событие имеет `event_id`;
- используется `event_time` (точность до секунд);
- фиксируется `received_at`.

### Семантика обработки (с Project №1.2)
Результат ingest классифицируется строго:

1. **duplicate** — `event_id` уже был принят ранее  
2. **rejected** — логическая ошибка (например, неподдерживаемый `entity_type`)  
3. **applied** — событие реально изменило current-state  
4. **stale** — событие проигнорировано из-за устаревшего `event_time`

> applied возвращается **только если UPSERT реально применился**  
> (rowcount > 0).

### Гарантии
- ingest не врёт о результате;
- current-state остаётся консистентным;
- read-side может доверять данным.

---

## 5. Read-side

### Основной контракт
- `/api/map` — **единственный источник данных для фронтенда**.

Принципы:
- фронт не агрегирует и не комбинирует данные;
- read-side возвращает полностью готовую “витрину на сейчас”;
- любые дополнительные эндпоинты считаются out-of-scope Project №1.

## 6. Визуализация

### Карта
- регионы: Россия, Казахстан, Беларусь;
- нейтральная минималистичная подложка;
- тонкие границы стран без подписей;
- свободный зум и перемещение;
- автоподбор масштаба при первом рендере.

### Склады
- все склады всегда видны;
- одинаковый визуальный стиль;
- размер точки зависит от количества товара;
- минимальный размер точки присутствует;
- рядом отображаются:
  - числовой остаток,
  - короткое имя склада + номер;
- подписи и числа:
  - скрываются при отдалении,
  - при наложении часть скрывается автоматически;
- tooltip при наведении — только число;
- без фокуса и подсветки.

### Межскладские перемещения
- между парой складов — одна “дорога”;
- две полосы = два направления;
- цвет полос одинаковый;
- толщина полосы = объём;
- отсутствие движения → тонкая приглушённая полоса;
- числовое значение по центру линии;
- геометрия важнее цифр.

### Поставка / продажа
- поставка: стрелка извне → склад;
- продажа: стрелка склад → вовне;
- подпись — абсолютное значение;
- автоматическое незаметное разведение геометрии при пересечениях.

---

## 7. Обновление данных и ошибки

### Обновление
- автообновление по глобальному интервалу;
- локальная пауза для пользователя;
- плавная перерисовка после паузы;
- локальный индикатор “данные обновляются”;
- отображается время последнего обновления
  (абсолютное, в локальном времени пользователя).

### Ошибки
- ошибки обновления отображаются ненавязчивым баннером;
- данные остаются последними успешными;
- без дополнительных индикаторов “устарело”;
- баннер исчезает автоматически при восстановлении.
